# 运营管理后台大规模内容方案

更新日期：2026-05-29

## 已落地

- 新增独立的作品库视图，后台人员可以看到全量作品、作者、IP/分身归属、热度分、播放、点赞、收藏、改编、完播率、举报数、商店状态、硬件状态和更新时间。
- 新增独立的 IP 池视图，后台人员可以看到 IP 类型、专区状态、热度、作品数、创作者数、分身数、硬件包数、专区门槛进度和近期风险率。
- 作品库支持搜索、来源筛选、运营状态筛选、热度/播放/完播/举报/更新时间排序、20/50/100 条分页。
- IP 池支持搜索、类型筛选、专区/风险状态筛选、热度/作品数/创作者/硬件包/风险排序、20/50/100 条分页。
- IP 池新增全网搜索入池面板，可以按 IP、角色、别名或题材关键词搜索候选，预览 IP 简介、完整角色简介、别名标签和权利提示后再收集入池。
- 全网候选命中既有 IP 时不再简单跳过，可以补全既有 IP 缺失的角色和简介。
- IP 池新增全 IP 角色简介总览，当前筛选下每个 IP 的角色、头像、简介和权利提示都能直接查看。
- 作品和趋势视图共用候选推进动作，热度高但未进入硬件链路的作品可以直接标为候选。
- IP 达到专区门槛时，后台可以直接发起专区申请。

## 大量试用结论

- 运营后台不能只展示审核队列。作品和 IP 是日常运营的主体，审核、治理、商店、硬件都应该能从作品/IP 维度回溯。
- 热度必须在作品表和 IP 表同时出现。作品热度用于挑选候选，IP 热度用于判断专区、活动和权利投入优先级。
- 大表格默认不能一次性渲染全部数据。当前版本使用分页渲染，E2E 已用 126 条作品验证搜索、翻页和每页数量切换。
- IP 的复杂度不只来自数量，还来自权利边界。主流外部 IP、社区 IP、平台原创 IP 必须分别运营，并在表格中保留风险率和专区门槛。
- 后台人员需要先筛出风险，再推进增长：举报优先排序、风险作品筛选、风险 IP 筛选是基础能力。

## 后续产品化方向

- 服务端分页和服务端排序：当作品达到万级时，前端分页应切到 API 查询参数，避免一次性拉取 feed。
- IP 运营详情页：点击 IP 后展示关联作品、核心创作者、分身、专区申请记录、权利材料和治理历史。
- 作品详情抽屉：在表格内快速查看剧情节点、素材来源声明、版本历史、评论/举报和硬件兼容报告。
- 批量操作：支持批量标记候选、批量冻结、批量导出审核样本、批量分配运营 owner。
- 运营看板分层：CEO/负责人看 IP 与收入趋势，审核看风险，硬件运营看制作队列，客服看诊断证据。
- 热度解释：把热度分拆成播放、完播、收藏、改编、举报扣分，减少运营误判。
