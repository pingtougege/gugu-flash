# UX Flow Plan

这份文档展开 `15. UI/UX 仍偏原型`。

目标不是先做漂亮页面，而是让用户清楚知道自己处在哪条链路：

```text
创作 H5
  -> 发布到内容流
  -> 申请上架商店
  -> 后台制作 HardwarePack
  -> 按设备购买 / 领取
  -> 下载并同步到当前设备
```

## 1. 核心结论

```text
1. 创作入口默认原创，二创作为同级但次要选项。
2. 二创必须从 IP 池选择 IP；没有 IP 时引导申请添加 IP。
3. 分身属于 IP 内角色，不作为全局自由角色池。
4. 有 IP 不等于有专区，创作时不强迫用户选择专区。
5. 专区是 IP 达标后申请开通的社区空间。
6. 商店上架和硬件下载必须与 H5 发布分开展示。
7. 用户前台不使用“硬件候选”这类运营语言。
8. 商店购买 / 领取必须先明确目标设备，因为权益按设备生效。
9. 移动端 App 是主体验，Web 分享页是辅助体验。
10. 新手引导采用渐进式提示，不做阻塞式长教程。
```

一句话：

```text
普通用户看到的是“做作品、发布、申请进商店、给这台设备下载”，运营后台才看到“候选、适配、审核、状态机”。
```

## 2. 主导航建议

MVP 移动端建议保留 5 个主入口：

```text
推荐
刷 H5 作品，进入互动，收藏，评论，二创。

IP
浏览 IP 池、角色分身、已开通专区、申请添加 IP。

创作
创建原创 / 二创 H5，编辑并发布。

吧唧
设备管理、当前运行内容、下载和同步状态。

我的
我的作品、申请上架、审核进度、订单和设备权益。
```

`好友 / 共创` 暂不作为 MVP 主入口。共创已经暂停，好友页可以后置为通知、评论互动、关注动态。

## 3. 创作流程

创作流程要轻，不要让新手一开始理解所有治理概念。

```text
Step 1: 选择作品类型
  原创（默认）
  二创

Step 2: 选择 IP
  原创：默认进入“我的原创企划”，也可以选择 / 创建原创 IP
  二创：必须从 IP 池选择 IP
  找不到 IP：申请添加 IP

Step 3: 选择角色分身
  只展示当前 IP 下可用角色
  没有角色时可选官方安全默认角色，或申请 / 创建角色

Step 4: 编辑内容
  标题、场景、台词、选项、上传素材、封面

Step 5: 发布确认
  发布到 H5 内容流
  明确提示：发布不等于上架商店，也不等于设备可下载
```

### 原创默认路径

普通用户点击“开始创作”时默认进入原创。

```text
开始创作
  -> 原创
  -> 我的原创企划 / 平台原创模板
  -> 选择角色分身
  -> 生成或编辑 H5
  -> 发布
```

界面文案不要一上来问“请选择 IPEntry 类型”。可以用：

```text
作品归属
原创
二创

原创企划
我的原创作品
创建新的原创企划
```

### 二创路径

二创路径必须明确 IP。

```text
开始创作
  -> 二创
  -> 搜索 IP 池
  -> 选择 IP
  -> 选择该 IP 内角色分身
  -> 编辑 H5
  -> 发布
```

如果搜索不到：

```text
没有找到这个 IP？
申请添加 IP
```

申请添加 IP 只代表进入 IP 池，不代表自动开通专区。

## 4. IP、分身、专区的前台关系

前台需要把三个概念排清楚：

```text
IP
作品归属容器。原创和二创都最终归到某个 IP / 原创企划。

分身
IP 内的角色。用户创作时选择的是“这个 IP 里的哪个角色来演出”。

专区
IP 达到作品、创作者、热度和风险门槛后，由用户申请开通的社区空间。
```

### 创作页不直接选专区

当前原型里的“专区选择”后续应改掉。

创作页应该选择：

```text
原创 / 二创
IP
角色分身
题材标签
```

作品发布后，如果该 IP 已有专区，可以自动出现在专区作品流里；如果没有专区，就只显示在推荐、作者页、IP 页和搜索里。

### IP 页

IP 页承担“池”的功能。

```text
IP 头部
  名称、类型、治理状态、简介

角色分身
  官方角色、用户角色、可申请角色

作品
  最新、热门、关注作者

商店 / 硬件
  已完成后台制作的 HardwarePack

专区入口
  已开通：进入专区
  未开通但达标：申请开通专区
  未达标：展示还差多少
```

### 专区页

专区不是 IP 的默认页面，而是达标后出现的社区空间。

```text
专区页
  IP 信息
  管理员和创始成员
  专区公告
  角色分身管理入口
  作品流
  活动 / 挑战
  商店 / 硬件精选
```

专区管理员可以管理专区秩序和角色申请，但不能绕过平台审核、强制推荐、强制上架或代表 IP 权利方授权。

## 5. 发布与上架的用户语言

前台不要直接暴露所有后端状态。

| 后端状态 | 用户可见文案 | 用户理解 |
| --- | --- | --- |
| `Work.draft` | 草稿 | 还没发布 |
| `Work.publish_submitted` | 发布处理中 | 正在做基础检查 |
| `Work.public_limited` | 已发布 | 可以被浏览，但推荐和商店能力有限 |
| `Work.public` | 已发布，可申请上架 | 可以进入商店申请 |
| `StoreListing.not_applied` | 未申请上架 | 只是 H5，不在商店 |
| `StoreListing.rights_review` | 上架审核中 | 平台在看权利和内容 |
| `StoreListing.production_queued` | 等待制作设备包 | 初审通过，排队制作 |
| `StoreListing.producing` | 正在制作设备包 | 后台正在适配硬件 |
| `StoreListing.pack_review` | 设备包复核中 | 制作完成，等待最终确认 |
| `StoreListing.listed` | 商店可领取 / 购买 | 可以给设备添加 |
| `HardwarePack.available` | 可下载到设备 | 当前设备满足条件时可下载 |
| `DeviceEntitlement.active` | 本设备已拥有 | 这台设备已买 / 已领取 |
| `DeviceInstall.installed` | 已装到本设备 | 设备里能继续使用 |
| `StoreListing.delisted` | 已下架 | 不再新购 / 新下载 |

## 6. 我的作品页

“我的作品”应成为状态解释中心。

每张作品卡展示：

```text
封面
标题
原创 / 二创 + IP
角色分身
H5 状态
商店状态
设备包状态
主按钮
```

按钮规则：

```text
草稿
  继续编辑

已发布但未申请上架
  申请上架商店

上架审核中
  查看进度

设备包制作中
  查看制作进度

已上架
  查看商店页

被拒
  查看原因 / 修改后重提

已下架
  查看影响范围
```

申请上架页必须解释：

```text
发布 H5 不等于上架商店。
上架后平台会制作设备内容包。
二创或外部素材需要用户承担授权风险并配合投诉处理。
通过后，用户可以按设备购买 / 领取和同步。
```

## 7. 商店与设备购买流程

因为权益按设备生效，商店首屏必须显示当前目标设备。

```text
商店
  -> 选择 / 确认目标设备
  -> 查看该设备可用内容包
  -> 购买 / 领取到这台设备
  -> 下载
  -> 同步
  -> 设备安装完成
```

按钮文案按设备状态变化：

```text
未拥有
  给这台设备领取
  给这台设备购买

已拥有未下载
  下载到手机

已下载未同步
  同步到这台设备

已同步
  已装到这台设备

设备不兼容
  当前设备不可用

已下架但已安装
  已装本设备，可继续使用

已下架且未安装
  已下架，无法下载
```

多设备用户要避免误解：

```text
这份内容已属于 Gugu Badge S3。
另一台设备需要单独领取 / 购买。
```

## 8. 新手引导

需要新手引导，但不做长教程。

建议用三种轻引导：

```text
空状态
  我的作品为空：先发布一个 H5。
  商店为空：已上架内容才会出现在这里。
  设备为空：绑定设备后才能同步内容。

流程卡
  第一次进入“我的”时展示三步：发布 H5、申请上架、同步设备。

上下文提示
  在发布按钮旁说明“发布到内容流，不会上架商店”。
  在申请上架页说明“上架后才会进入设备包制作”。
  在商店页说明“购买权益按当前设备生效”。
```

不建议 MVP 做全屏强制教学，容易打断内容消费。

## 9. Web 与移动端优先级

移动端 App 优先。

原因：

- 创作、互动、设备绑定、BLE 同步都更依赖手机。
- 商店购买 / 下载 / 同步必须识别当前设备。
- Web 更适合 H5 分享、作品预览、活动页、轻量 IP 页。

优先级：

```text
P0 移动端主流程
  推荐、互动、创作、我的、商店、设备同步。

P1 Web H5 分享页
  打开作品、互动、跳转 App。

P2 Web 创作后台
  给重度创作者编辑复杂场景和素材。

P3 Web 运营后台
  审核、适配、商店、设备包管理。
```

## 10. MVP 改造顺序

### Phase 1: 状态文案收敛

- 把前台“硬件候选”改为“可申请上架 / 制作设备包中 / 可下载”。
- 作品卡拆出 H5 状态、商店状态、设备状态。
- 商店按钮改成按设备的动词。

### Phase 2: 创作流程重排

- 默认原创。
- 二创必须选 IP 池。
- 分身列表跟随 IP。
- 移除创作页里的必选专区。
- 发布确认页明确“发布不上架”。

### Phase 3: IP 与专区入口

- 增加 IP 页。
- IP 页展示角色分身、作品、商店内容、专区申请状态。
- 达标 IP 显示申请开通专区入口。
- 专区页只展示已开通专区。

### Phase 4: 商店和设备链路

- 商店首屏固定当前设备。
- 购买 / 领取按钮按设备生效。
- 设备页展示已拥有、已下载、已同步、已安装。
- 下架后展示“已安装可继续使用 / 不可新下载”。

### Phase 5: 运营后台语言隔离

- 官方台改为运营后台入口，不混在普通用户主流程里。
- “候选、适配、兼容报告、制作队列”只给运营看。
- 用户只看到审核和制作进度。

## 11. 当前原型需要调整的点

- 创作页当前有“专区”必选，这会误导用户以为有 IP 就有专区，应改为 IP 和角色分身选择。
- 角色分身当前像全局列表，后续应按 IP 过滤。
- 商店当前虽然有目标设备，但要更明确“权益按当前设备生效”。
- 我的作品页需要把 H5 发布、商店申请、硬件包制作拆成进度。
- 官方精选台可以保留原型能力，但名称和入口应转为运营视角。
- 共创入口和好友页暂时降级，避免和已暂停的共创方向冲突。

## 12. 已确认决策

1. 创作默认原创，二创作为清晰可见的第二选项。
2. 二创必须选择 IP 池里的 IP。
3. 分身是 IP 内角色。
4. 创作时不直接选择专区。
5. 有 IP 不等于有专区。
6. 专区达标后由用户申请开通。
7. 需要新手引导，但使用渐进式提示和空状态，不做阻塞式长教程。
8. 移动端 App 优先，Web 分享页辅助。
9. 商店购买 / 领取按设备展示和结算。
10. 前台不使用“硬件候选”等运营语言。
